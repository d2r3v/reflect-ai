**Reflect AI** is a safety-aware support companion built on FastAPI and React Native. It features deterministic crisis bypass, a sticky post-crisis cooldown state machine, and mode-aware LLM response routing.

Rather than relying purely on unconstrained prompt generation, Reflect AI enforces a structured execution pipeline that prioritizes safety, risk classification, and auditability.

## Key Features

- **Mode-Aware Response Generation**
  Responses are generated by `CompanionBrain`, which applies a distinct system prompt based on the active `ResponseMode` (`reflect`, `vent`, `plan`, `grounding`).

- **Deterministic Crisis Bypass**
  Critical-risk triggers bypass the LLM execution path entirely via `CrisisBrain`, immediately returning a deterministic crisis response with 988 and Crisis Text Line (741741) resources.

- **Sticky Crisis Cooldown State Machine**
  Prevents rapid state bouncing after a crisis event. The conversation enters a `post_crisis` state and holds a safety floor, requiring 3 consecutive low-risk messages **and** a 5-minute cooldown (both configurable) before returning to normal modes.

- **Crisis-Aware React Native Client**
  The mobile chat UI renders a warm crisis card with a direct 988 call CTA on critical messages, plus a softer post-crisis banner that persists throughout the cooldown window.

- **Safety Event Auditing**
  Elevated-risk inputs and state transitions are logged to the database (`SafetyEvent`) with risk level, response mode, and bypass flags for later auditing.

- **End-to-End JWT Authentication**
  Complete authentication layer using PBKDF2-HMAC-SHA256 password hashing (no platform-specific dependencies), JWT access tokens, on-device token persistence, and automatic session restoration.

## System Architecture

```text
User Input ──► Safety Engine (Classifier & Cooldown State Machine)
                    │
                    ├── Critical ──► CrisisBrain (Deterministic 988 Bypass)
                    │
                    └── Low/Med/High ──► CompanionBrain ──► OpenAI API (Mode Prompting)
                                              │
                                              ▼
                                    Safety Event & DB Persistence
```

Risk levels map to response modes as follows: `low → reflect`, `medium → vent`, `high → grounding`, `critical → crisis` (LLM bypassed).

## Quick Start & Setup

### 1. Backend Setup (FastAPI)

```bash
cd backend
python -m venv venv
# Linux/Mac: source venv/bin/activate
# Windows (PowerShell): .\venv\Scripts\Activate.ps1

pip install -r requirements.txt

# Configure secrets
cp .env.example .env          # Windows: copy .env.example .env
# Edit .env to set JWT_SECRET and OPENAI_API_KEY.
# DATABASE_URL defaults to a local SQLite file; set a postgresql:// URL to use Postgres.

# Run database migrations
alembic upgrade head

# Start development server
uvicorn src.main:app --host 0.0.0.0 --port 8000 --reload
```

> Binding to `0.0.0.0` makes the server reachable from mobile emulators and physical devices on your local network.

### 2. Frontend Setup (React Native / Expo)

```bash
cd mobile
npm install

# Start the Expo development server
npx expo start --android
```

## Security

- Authentication and authorization are enforced at the API layer.
- Passwords are hashed with PBKDF2-HMAC-SHA256 (260k iterations, random per-user salt).
- Access tokens are stored securely on-device; the backend never exposes raw credentials or secrets.
- Critical-risk crisis responses are deterministic and never routed through the LLM.

## Planned Roadmap

- **Vector Memory Retrieval** — Inject semantically relevant historical context from past sessions into the current execution window (`MemoryService` and the client `MemoryInspector` screen are in place as scaffolding).
- **Conversation History as Context** — Pass the last N messages to give the model within-session memory.
- **Streaming Tokens** — Token-by-token WebSocket/SSE streaming to the React Native interface.
- **Multi-Provider LLM Fallbacks** — Dynamic failover across OpenAI, Anthropic, and local Ollama instances via the `LLMProvider` interface.
- **Tool Orchestration** — Let the LLM invoke structured tools (e.g. mood logging) through the existing `ToolRegistry`.
- **Advanced Safety Policies** — Replace keyword matching with an ML-based risk classifier.
